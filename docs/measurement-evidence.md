# 三端统一的三维画像统计

## 计算口径

每类占比 = 该类标签命中数 / 当前范围最终有效对话数。先按会话选择证据，再汇总到任务、轮次、学生、班级和全体；不对各人的百分比做简单平均，也不额外归一化到 100%。

来源选择顺序（同一个会话不能重复计数）：

1. 管理员已上传完整校对集时，使用该会话最新上传版本的文本数量和最终标签；这是管理员对现有结果的明确校正。
2. 否则，使用当前权威转录的最新抽取版本中，完成整批人工复核后接受的有效对话数量。对同一候选，已完成专家共识/仲裁优先于模型标签。已接受但分类失效/待分类的文本保留在分母内，并提示尚未分类数量，不伪造为某一类别。
3. 没有完整候选复核集，但有已完成专家批次时，按每个会话最新完成批次的有效编码单元统计。不同任务分别编码的批次都计入，不再只取整轮的最后一个批次。
4. 均无有效复核/校对数据时，只使用当前权威转录最新抽取版本的真实、成功分类且未排除的三类标签，以三类标签总数作分母。页面标记为“回退（暂定）”，不冒充完成正式复核。
5. 分母为 0 时无可用画像。存在真实复核对话、且全部标签为非元认知时，三维为真实的 0；未完成分类造成的全零不显示为正式零分。

例如：最终有效对话 12 条，监控 3 条、调控 4 条、评估 2 条，其余 3 条为非元认知，则分别为 25%、33.3%、16.7%，并不合计为 100%。这些指标不是能力等级或心理测量常模。

API 中 `total` 仍指三类标签数之和，`effective_dialogue_count` 才是分母；`denominator_breakdown` 记录各来源分母条数，`fallback_dialogue_count` 与 `unclassified_count` 用于提示数据边界。模型分类处理覆盖率仍按当前候选记录计算，不因管理员上传校对而改变。

## 管理员上传

入口：管理员端的“班级宏观实证分析与全链路可观测大屏” → “管理员 · 上传有效对话校对”。教师、学生没有入口，服务端也禁止其调用上传、模板接口。

- 下载 CSV 模板，使用 UTF-8 编码。
- 三列：`会话ID,校对文本,最终标签`（也接受 `session_id,text,label`）。会话 ID 在转录校订页/现有导出数据中取得，不能填账号或轮次 ID。
- 一个会话对应一个人的一次任务。每行是一条完整有效对话；同一文件可包含多个会话。
- 标签：`0=非元认知、1=监控、2=调控、3=评估`，也接受对应中文或 `non_metacognitive/monitoring/regulation/evaluation`。
- 非元认知仍进入有效对话分母；这不会把 0 类重新加入模型训练。
- 必须提供每个列出会话的**完整**校对集，不能只上传新增片段、三类命中句或单独修改分母；上传同时替换该会话统计所用分子和分母，以保证范围匹配。
- 仅限已完成测评。每次最多 5 MB、10000 条、100 个会话。未知会话、空文本、无效标签等导致整个文件拒绝，不产生半份结果。
- 每次上传保存新版本、操作者、文件指纹和审计记录；不覆盖 ASR 原文、原始音频、候选文本及专家原始编码。旧上传版本保留在数据库，未涉及的会话不受影响。
- 上传后当前页面重新查询结果；其他端点击刷新或重新进入即可按同一规则重新计算。当前并非跨浏览器实时推送。
- 删除对应会话时，上传校对版本由外键级联删除；审计仅保留操作与版本 ID，不保存校对文本。

接口：

- `GET /api/reports/measurement-corrections/template`：管理员下载模板。
- `POST /api/reports/measurement-corrections`：管理员 multipart 上传，字段 `file`、`confirmed=true`。
- `GET /api/reports/metacognition-measurements`：学生本人历史轮次；分页。
- `GET /api/reports/metacognition-measurements/{run_id}?task_id=...`：学生本人轮次/任务。
- `GET /api/research/macro-analytics`：教师管理范围/管理员范围及汇总对比；学生仅本人明细与班级/全体汇总。

## 部署兼容

### 学生历史轮次与任务切换

- 轮次列表按完成时间倒序，读取全部分页；未分类、未发布综合报告的已完成轮次也保留。首次进入默认最新完成轮次，手动选择后刷新保留选择。
- 下拉项显示完成时间、任务及“已有画像 / 暂定结果 / 待分类”。回退分母或部分对话尚未分类时标记暂定；无结果时不绘制虚假的零分雷达图。
- 整轮、单任务使用独立快照。切换轮次重置为整轮；单任务失败可以单独重试，切回整轮立即清除任务错误，不让较慢的旧请求覆盖新选择。
- 本地 `dev.ps1` 已与生产共用 `migrate_all.py`，任一迁移失败都会阻止后续启动。Phase 33 在保留外键和原有数据的前提下，将旧的 `UNIQUE(run_id)` 替换为 `UNIQUE(run_id, scope_key)`；只新增后者却未移除前者会导致单任务查询插入快照时出现 500。

新增 `measurement_corrections` 表，迁移脚本 `backend/scripts/migrate_phase34.py` 已纳入 `migrate_all.py`。只新增表，不修改录音、转录或旧测评数据；三维快照读取时重新计算。

部署需执行新迁移并更新前后端。不能只替换前端。正式打包的版本标记已提升至 `schema_phase=34`，应使用下次生成的新包，不复用旧 v2 包。本次没有改依赖、Dockerfile 或环境变量，也没有自动部署服务器。

## 验证

后端测试：`python -m unittest tests.test_measurement_evidence tests.test_metacognition_measurement tests.test_metacognition_distribution`。

前端状态回归：在 frontend 执行 `node --test tests/measurement-state.test.mjs`；构建执行 `pnpm build`。

设置 `MIGRATION_TEST_MYSQL=1` 后可执行 `python -m unittest tests.test_measurement_correction_migration`，会创建随机命名的隔离测试库，重复运行迁移并验证保留版本及会话级联删除；不会修改业务库。
