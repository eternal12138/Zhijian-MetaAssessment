# 仓库上传前核查（2026-08-28）

## 范围与结论

针对前次 GitHub CI 失败，检查当前已跟踪源码、完整自动测试、迁移入口、构建配置和上传边界。以下为实际本地结果，不等同于生产环境所有功能已完成端到端验收。

## 修复

- 部署和时间契约测试仍要求 `dev.ps1` 逐个列出迁移脚本，与当前统一 `migrate_all.py` 入口不符。改为检查真实迁移注册表，并验证开发与生产都调用同一入口、迁移失败时不会继续初始化。
- `ModelTrainingJob.active_scope` 使用 MySQL 的 `IF()`，较旧 SQLite 无法建表。改为两者通用的 `CASE WHEN`，同时在 ORM 声明已有生产迁移中的单一启用模型唯一索引。
- 新增真实数据库写入测试：可保留多个未启用版本、拒绝同时启用两个模型、支持停用和回滚。测试显式禁止 SQLite 的 `IF()`，防止本地新版 SQLite 掩盖兼容性问题。
- CI 将研究测试拆为独立任务并安装其评估依赖；不将 pandas、matplotlib 等研究依赖加入生产依赖。
- CI 增加前端回归测试和隔离的 MySQL 8.4 迁移测试。测试数据库使用随机专属名称，不连接生产服务。
- 前端雷达图测试改从直接依赖 `vue/compiler-sfc` 导入编译器，不依赖本地偶然存在的间接包入口。

已有 MySQL 数据库中 `IF()` 生成列与新表达式语义相同；迁移仍按存在性检查执行，不重写现有数据、不删除已有模型。此次不增加 schema phase。
