# 2026-08-28 学生雷达图任务范围：迁移兼容修正版

本次发布：`metacognition-deploy-20260828-student-radar-task-scope-v2`。
请使用同名 ZIP 和 `.zip.sha256`，不要继续部署不带 `-v2` 的旧包。

## 修复内容

生产库由 ORM 创建的旧唯一索引名为 `run_id`，而第 32 阶段 SQL 使用
`uq_metacognition_measurement_run`。原第 33 阶段脚本只检查后者，而且先删除旧索引。
前一种会遗留“一轮只能一条”的唯一限制；后一种可能因索引被外键依赖而删除失败。

修正版先创建并验证 `(run_id, scope_key)` 联合唯一索引，再按实际索引定义移除
所有非主键、完整单列 `run_id` 唯一索引，不依赖旧名字。保留外键、主键、其他索引和已有记录。
支持已经加列、已创建新索引、旧脚本中途失败后的重试。MySQL DDL 不能靠事务整体回滚，
所以迁移前必须保留数据库备份，失败后先查日志，不删除表、不关闭外键检查。

## 更新操作

假设包上传到 `/opt/metacognition`。逐行执行，任一命令报错即停止后续操作。
不要删除 `.env.production`、DATA_DIR 或 Docker 数据卷，也不要使用 `down -v`。

```bash
cd /opt/metacognition
sha256sum -c metacognition-deploy-20260828-student-radar-task-scope-v2.zip.sha256
```

这里不重复压缩录音和导出结果。请确认已有这些文件的可靠备份；本次更新不替换它们。

```bash

CODE_BACKUP="/opt/metacognition-code-backups/$(date +%Y%m%d-%H%M%S)"
install -d -m 0700 "$CODE_BACKUP"
tar --exclude='backend/.venv*' --exclude='backend/uploads' --exclude='backend/exports' --exclude='backend/models' --exclude='frontend/node_modules*' --exclude='frontend/dist' -czf "$CODE_BACKUP/code-before.tar.gz" backend frontend deploy compose.yaml .env.production

```

如校验提示已退役旧文件仍存在，先确认上述源码备份成功，仅处理提示的两个退役文件，
不删除其他文件，处理后重新校验。

### 3. 构建（此时旧容器继续服务）

```bash
docker compose --env-file .env.production --profile tunnel config --quiet
docker compose --env-file .env.production --profile tunnel build --progress=plain
```

无需 `--no-cache`。系统依赖步骤应优先使用 CACHED；缓存或基础镜像不同仍可能重新安装。
构建失败时不要停止旧容器，先查失败原因。

### 4. 维护窗口：无正在进行的测评、复核、训练或导出后执行

暂停业务写入后做最新数据库备份（不压缩录音），数据库自身保持运行：

```bash
docker compose --env-file .env.production stop frontend backend asr-worker extraction-worker model-training-worker export-worker
install -d -m 0700 /opt/metacognition-db-backups
umask 077
docker compose --env-file .env.production exec -T db sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump --single-transaction --routines --triggers -u root "$MYSQL_DATABASE"' > "/opt/metacognition-db-backups/before-scope-v2-$(date +%Y%m%d-%H%M%S).sql"
```

确认备份命令无错误且退出码为 0 再迁移（可紧接上一条执行 `echo $?`）。
不要因为备份文件存在就认定成功，失败会留下不完整文件。

```bash
docker compose --env-file .env.production run --rm --no-deps storage-permissions
docker compose --env-file .env.production run --rm --no-deps migrate
```

必须看到 `Phase 33 scoped metacognition measurement migration completed.`，整个迁移命令也需成功退出。
若任一步失败，不启动新版服务，不手动删除测量表，保留输出用于排查。
