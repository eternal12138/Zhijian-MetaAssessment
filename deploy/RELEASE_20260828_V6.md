# 画像取数、草稿审阅及管理分页修复（v6）

发布包：`metacognition-deploy-20260828-radar-evidence-v6.zip`

## 更新范围

- 统一 AI 评估与三端画像的抽取版本选择。新任务排队或失败时，保留同一权威转录下的上一成功版本，包括已标记为 superseded 的成功历史记录；新版成功后不混用旧标签。
- 保留管理员校对、人工复核及三类标签回退的分母规则；学生切换轮次时刷新，并显示任务状态、抽取版本及分类模型。
- AI 评估区分可用分类和当前模型已分类，非法分类输出明确报错。
- 最近报告支持查看草稿、审阅确认和受控发布；保留教师班级权限、学生仅查看已发布报告的限制。
- 任务顺序分配、研究数据质量、最近报告、待生成报告列表分页。
- 保留前版雷达图居中、浅深色适配、字体和 Logo 读取权限修复。

## 适用前提

适用于此前已完成 v3/阶段 34 数据库更新、且 v4/v5 已正常运行的服务器。本次未新增数据库字段、迁移、依赖或 Docker/Compose 配置变更。更新 backend 和 frontend 即可；不需要重建数据库、ASR、抽取、训练及导出 worker，也不需要重启 Cloudflare Tunnel。

若不是从此前正常运行的版本升级，先确认数据库结构，不能直接跳过历史迁移。不要仅凭 release.json 判断数据库已迁移。

本包不包含真实环境配置、数据库、录音、导出包或模型产物。不会覆盖 `.env.production` 或 `/srv/metacognition` 数据。保留上次正常发布包作为回退依据；本次不执行全量录音备份，不清理缓存或历史数据。

## 上传后执行

将 ZIP 和配套 `.zip.sha256` 一起上传到 `/opt/metacognition`。避开录音、提交和报告生成时段；容器替换会有短暂中断。每行单独执行，失败时停止。

```bash
cd /opt/metacognition
sha256sum -c metacognition-deploy-20260828-radar-evidence-v6.zip.sha256 && unzip -q -o metacognition-deploy-20260828-radar-evidence-v6.zip
python3 deploy/verify-release.py /opt/metacognition
docker compose --env-file .env.production build --progress=plain backend frontend && docker compose --env-file .env.production up -d --no-deps --no-build backend frontend
curl -fsS --retry 12 --retry-delay 3 --retry-connrefused --max-time 10 http://127.0.0.1:8080/api/health/ready && curl -fsS --max-time 20 http://127.0.0.1:8080/release.json
```

健康检查应返回 `status: ok`；release_id 应为 `metacognition-deploy-20260828-radar-evidence-v6`。

不要额外运行 backup.sh、全服务 build、up --build、migrate 或 prune。构建使用现有缓存，不加 --no-cache；缓存缺失时依赖层仍可能重新下载。构建失败不会执行同一行后面的容器替换。

校验失败时不要继续部署。若出现旧文件残留提示，先核实并处理提示中的具体文件，不要跳过检查或删除业务数据。

## 上线验收

1. 强制刷新网页；确认版本号正确。
2. 学生查看此前空白轮次，切换任务和轮次，确认数据及时更新；排队/失败的新抽取应注明正在使用的旧版本。
3. 对同一学生、任务核对 AI 评估与三端画像。人工/管理员校对具有优先级，已分类数量不等于有效对话分母。
4. 新权威转录或新成功抽取尚未分类时，页面应如实提示，不沿用旧文本标签。仅对这些缺失部分补跑分类，不要求全部重跑。
5. 管理员/教师打开报告草稿，查看发布检查并审阅确认；学生不能提前查看草稿。确认四处列表分页正常。
