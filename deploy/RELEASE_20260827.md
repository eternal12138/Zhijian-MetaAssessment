## 避免再次部署到旧版前端

上传 ZIP 和同名 `.zip.sha256` 校验文件后，在两者所在目录执行（将文件名替换为本次实际文件名）：

```bash
sha256sum -c metacognition-deploy-20260827-student-verified-v2.zip.sha256
```

请先按上面的顺序备份、覆盖解压。解压后，使用包内校验器检查源文件，允许两个待退役旧文件暂存：

```bash
cd /opt/metacognition
python3 deploy/verify-release.py /opt/metacognition --allow-retired
```

确认两个旧文件已备份后，仅移除上面列出的两个已退役文件，再严格校验：

```bash
python3 deploy/verify-release.py /opt/metacognition
docker compose --env-file .env.production --profile tunnel config --quiet
docker compose --env-file .env.production --profile tunnel build --progress=plain
```

**build 仅构建镜像，不会更新正在运行的容器。** 构建成功且确认无进行中的测评、复核、训练与导出后，进入维护窗口，依次执行；任一步失败先停止后续步骤并检查日志：

```bash
docker compose --env-file .env.production stop frontend backend asr-worker extraction-worker model-training-worker export-worker
docker compose --env-file .env.production up -d db
docker compose --env-file .env.production run --rm --no-deps storage-permissions
docker compose --env-file .env.production run --rm migrate
docker compose --env-file .env.production --profile tunnel up -d
docker compose --env-file .env.production --profile tunnel ps -a
curl -fsS --max-time 20 http://127.0.0.1:8080/api/health/ready
curl -fsS --max-time 20 http://127.0.0.1:8080/release.json
curl -fsS --max-time 20 https://meta.21050411.xyz/release.json
```

容器部署版 `/release.json` 的 `release_id` 必须等于本次 ZIP 文件名（去掉 `.zip`）。该接口只公开发布编号、构建时间和迁移阶段，不含密钥或业务数据。

- 服务器本机标识仍旧：检查解压目录、Compose 项目、镜像构建目录及容器是否确实更新。
- 本机正确、域名旧或报错：检查 Cloudflare 缓存和隧道目标，不要反复迁移数据库。
- 两处标识一致但浏览器旧：强制刷新或用隐私窗口复测，再检查 HTML 缓存。
- 新学生卡片显示“暂无历史测量结果”或“本轮暂无足够的有效对话数据”：这是数据状态，不等于更新失败。

不要将 RELEASE_MANIFEST.json 的校验误认为发布者签名；还应核对独立提供的 ZIP SHA-256。验证器不会读取或覆盖服务器 .env.production、数据库或模型产物。
