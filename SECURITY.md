# Security Policy / 安全声明

## 中文

如果您认为在本软件中发现了安全漏洞，请不要创建公开 Issue，也不要在公开讨论区披露漏洞细节。请通过本 GitHub 仓库的 **Security（安全）** 选项卡，以私密方式向我们提交安全漏洞报告。

提交漏洞后，我们将在内部审查该报告，并根据需要联系您，提出补充问题或说明后续处理步骤。

如果报告被确认并接受，我们将申请 CVE 编号，并创建本仓库的私有分支或私有 Fork 来修复该问题。修复对应的 Pull Request 合并后，我们将在 GitHub 仓库中发布安全公告。

在安全公告正式发布之前，请不要在 GitHub 安全公告之外讨论、传播或公开披露该漏洞。这有助于在修复方案可用之前保护系统用户和研究数据。

安全报告中请尽量包含：

- 受影响的版本、提交或部署方式；
- 漏洞类型、影响范围和可能的攻击场景；
- 可复现的操作步骤或最小化验证样例；
- 已采取的临时缓解措施（如有）；
- 您希望我们采用的署名方式，或是否希望匿名。

请勿在报告中包含不必要的真实被试录音、转录、问卷、身份信息、生产密钥或数据库副本。如需提供敏感证据，请先在私密报告中说明，由维护者确认安全的传输方式。

## English

If you think you have found a security vulnerability in our software, please do not open a public issue or disclose the vulnerability in a public discussion. Report it to us privately using the **Security** tab on the GitHub repository.

After you have submitted the vulnerability, we will review the report internally and respond with any questions or next steps.

If the report is accepted, we will request a CVE and create a private branch or private fork of the repository to work on the issue. Once the corresponding pull request is merged, we will publish the security advisory on the GitHub repository.

We ask that you do not discuss or disclose the vulnerability outside the GitHub security advisory until the advisory is published. This helps protect users and research data until a fix is available.

When possible, include:

- the affected version, commit, or deployment configuration;
- the vulnerability type, impact, and potential attack scenario;
- reproducible steps or a minimal proof of concept;
- any temporary mitigation already applied; and
- your preferred attribution, or whether you wish to remain anonymous.

Do not include unnecessary real participant recordings, transcripts, questionnaire responses, identifying information, production secrets, or database copies. If sensitive evidence is required, first describe it in the private report and wait for the maintainers to confirm a safe transfer method.
